2. Visual replication requirements

- Overall layout.
- Header.
- Navigation.
- Typography.
- Colors.
- Icons.
- Images.
- Cards.
- Buttons.
- Inputs.

Match the original reference as closely as technically possible.

3. Reusable components

Use shared components and design tokens.

Avoid:

- Duplicated UI code.
- Inconsistent spacing.
- Different button styles across modules.
- Random colors.
- Inconsistent icon sizes.

4. Important requirements

- Reproduce the original mobile-first appearance.
- Preserve Arabic and English layout support.
- Ensure scrolling works correctly.
- Handle keyboard and safe areas.
- Keep navigation visually consistent.
- Use genuine assets where supplied.
- Do not substitute unrelated stock imagery for reference images.

5. Validation

Compare each implemented screen against its corresponding reference screenshot.

Record visual differences and correct them.

Do not claim pixel-perfect completion without screenshot comparison.

6. Deliverables

Do not proceed to backend or business logic until the screen implementation has been reviewed.
